# SCSS Styles Spec (Angular + SCSS)

## Purpose

Определение правил стилизации проекта "Девять жизней". Цель: поддерживаемая, модульная верстка с использованием SCSS, изолированная внутри Angular-компонентов с использованием методологии БЭМ.

## Stack

- СУБПРОЦЕССОР: SCSS (Sassy CSS)
- Методология именования: БЭМ (Block, Element, Modifier) для чистоты каскада
- Изоляция стилей: Angular View Encapsulation (Emulated по умолчанию)

**НЕ используем — никогда:**

- Tailwind CSS, Bootstrap и любые другие утилитарные или UI-фреймворки
- Инлайн-стили (`style="..."`), кроме редких динамических расчетов через Angular (например, `[style.width.%]="progress()"`)
- Глобальные селекторы тегов (например, `div`, `p`, `button`) внутри компонентов без привязки к классам

## Архитектура стилей в Angular

### 1. Компонентные стили (Локальные)

Каждому компоненту принадлежит свой файл `*.component.scss`.

- **Правило БЭМ:** Сам Angular-компонент является **Блоком** (например, `.pet-card`). Все элементы внутри него пишутся через двойное подчеркивание (`.pet-card__name`), а состояния — через двойной дефис (`.pet-card__name--highlighted`).
- Благодаря изоляции Angular, вы можете безопасно использовать амперсанд `&` в SCSS:

  ```scss
  .pet-card {
    display: flex;
    border-radius: 12px;

    &__name {
      font-size: 18px;
      font-weight: bold;
    }

    &--fostered {
      background-color: #fffbeb; // модификатор состояния "на передержке"
    }
  }
  ```

### 2. Глобальные стили (`src/styles/`)

Глобальные файлы нужны только для общих настроек и переменных.

- `src/styles/_variables.scss` — SCSS-переменные или CSS Custom Properties (цвета, шрифты, отступы).
- `src/styles/_mixins.scss` — Миксины для переиспользуемых стилей (например, брейкпоинты для адаптивности).
- `src/styles/main.scss` — Точка сборки, сброс стилей (Reset/Normalize) и базовые шрифты сайта.

## Правила Дизайн-системы

- **Шрифты:** Базовый размер текста в анкетах и каталоге — не менее `16px`. Текст должен быть контрастным и легко читаемым.
- **Цвета:** Использовать только переменные (CSS custom properties / SCSS-переменные из `src/styles/_variables.scss`). Актуальная палитра, роли цветов и правила их применения описаны в `docs/design-direction.md` — не задавать цвета вручную и не опираться на устаревшие описания палитры вне этого файла.
- **Скругления:** Мягкие, радиус карточек подопечных — от `12px` до `16px`. Никаких острых углов или агрессивного неонового свечения.

## Адаптивность (Responsive)

Адаптивность реализуется через SCSS-миксины медиа-запросов (Mobile-First). Медиа-запросы пишутся **внутри** селектора БЭМ-элемента, а не в конце файла:

```scss
.catalog-grid {
  display: grid;
  grid-template-cols: 1fr; // Мобильные телефоны
  gap: 16px;

  @include respond-to(tablet) {
    grid-template-cols: repeat(2, 1fr); // Планшеты
  }
  @include respond-to(desktop) {
    grid-template-cols: repeat(3, 1fr); // Компьютеры
  }
}
```

## Правила для ИИ (Claude Constraints)

AI должен:

- Писать стили строго в локальных `*.component.scss` файлах для каждого компонента.
- Соблюдать БЭМ-именование классов для всех элементов интерфейса.
- Активно использовать возможности SCSS: вложенность (nesting), переменные и амперсанд `&`.
- Ориентироваться на визуальную структуру и логику из папки `reference/` (Елабужская группа «9 Жизней»).

AI не должен:

- Использовать утилитарные классы Tailwind.
- Писать стили, ломающие изоляцию компонентов (избегать `:host ::ng-deep` без крайней необходимости).
