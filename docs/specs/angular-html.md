# Angular HTML Templates Spec

## Purpose

Определение правил написания HTML-шаблонов (`*.component.html`) для проекта "Девять жизней". Цель — создание чистой, семантичной, производительной и доступной разметки, которая легко читается разработчиком и корректно генерируется ИИ.

## Общие правила разметки

- **Семантика прежде всего:** Использовать правильные теги HTML5 (`<header>`, `<main>`, `<section>`, `<article>`, `<footer>`, `<nav>`) вместо сплошных `<div>`. Карточка котика — это `<article>`, список карточек — `<section>`.
- **Именование классов (БЭМ):** Все теги должны иметь классы, оформленные строго по методологии БЭМ, как описано в `docs/specs/styles.md`. Инлайн-стили (`style="..."`) запрещены.
- **Доступность (A11y):** Все изображения котиков (`<img>`) обязаны иметь понятный атрибут `alt` (например, `alt="Фото кота Мурзика"`). Интерактивные элементы, не являющиеся ссылками, должны быть тегом `<button>`, а не `<div>` с кликом.

## Синтаксис Angular 17+ (Строгие правила)

### 1. Управление структурой (Control Flow)

Категорически **запрещено** использовать старые директивы `*ngIf`, `*ngFor` и `*ngSwitch`. Используем только новый, встроенный синтаксис Angular:

- **Условия (`@if` / `@else`):**
  ```html
  @if (pet().status === 'Ищет дом') {
  <span class="pet-card__badge pet-card__badge--green">Ищет дом</span>
  } @else {
  <span class="pet-card__badge pet-card__badge--amber">На передержке</span>
  }
  ```
- **Циклы (`@for`):** Обязательно указывать уникальный `track` (обычно по `id`). Для вывода пустых состояний (когда котиков по фильтру не найдено) всегда использовать `@empty`:
  ```html
  <div class="catalog__grid">
    @for (pet of pets(); track pet.id) {
    <app-pet-card [pet]="pet" class="catalog__item"></app-pet-card>
    } @empty {
    <p class="catalog__empty-text">По вашему запросу пушистиков не найдено.</p>
    }
  </div>
  ```

### 2. Вывод данных и Сигналы (Signals)

Так как проект использует `OnPush` и Angular Signals, вывод данных в шаблоне имеет свои особенности:

- **Скобочки обязательны:** При чтении сигналов в шаблоне всегда вызывайте их как функцию со скобками `()`.
- **Интерполяция:** Строго через двойные фигурные скобки `{{ }}`. Все строки, выводимые из модели, автоматически экранируются Angular от XSS-атак.
- **Пример:** `{{ pet().name }}` или `{{ pet().age }} года`.

### 3. Привязка данных и Событий (Binding)

- **Property Binding (Свойства):** Привязка динамических атрибутов (ссылки на фото ВК, свойства `disabled` кнопок) делается через квадратные скобки: `[src]="pet().avatarUrl"`.
- **Event Binding (События):** Слушатели событий (клики, ввод текста) пишутся в круглых скобках: `(click)="onOpenDetails(pet().id)"`.
- Имена методов-обработчиков событий должны начинаться с префикса `on` (например, `onFilterChange()`, `onAdoptClick()`).

### 4. Оптимизация производительности в HTML

- **Ленивая загрузка изображений:** Для картинок в галерее, которые находятся ниже первого экрана, обязательно добавлять атрибут `loading="lazy"`, чтобы приложение не скачивало все фото котиков из ВК одновременно при старте.
- **Минимум логики в HTML:** Шаблон должен быть «глупым». Запрещено писать сложные логические выражения прямо в HTML. Если нужно сложное условие, вынесите его в TypeScript-класс в виде `computed()` сигнала.

## Правила для ИИ (Claude Constraints)

AI должен:

- Генерировать HTML строго с использованием синтаксиса `@if`, `@for` и `@empty`.
- Автоматически прописывать скобочки `()` у сигналов при их выводе в HTML.
- Добавлять комментарии на русском языке к ключевым блокам разметки, если они содержат сложную Angular-логику.
- Ограничивать верстку семантическими тегами с БЭМ-классами без использования Tailwind или инлайн-стилей.
