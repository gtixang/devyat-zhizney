# Code Style

## Общие правила

- писать простой и читаемый код;
- не создавать абстракции заранее;
- не создавать универсальные решения без реальной необходимости;
- не писать слишком большие функции и методы;
- одна основная ответственность на файл/класс/функцию;
- предпочитать ранний `return` вместо глубокой вложенности;
- давать понятные имена переменным, функциям, классам и компонентам;
- избегать ненужных сокращений;
- придерживаться единого стиля во всём проекте;
- не дублировать существующую логику без необходимости.
- Код стайл по каждой технологии описаны в отдельных файлах:
- docs/specs/styles.md — работа с SCSS стилями
- docs/specs/ts.md — работа с ts кодом
- docs/specs/angular-html.md — работа с шаблоном HTML (добавить, ARIA, доступность, семантические теги)

---

## TypeScript

- использовать `strict` mode;
- не использовать `any` без обоснованной необходимости;
- предпочитать точные типы вместо `any`;
- использовать `interface` и `type` по назначению;
- не создавать типы, которые используются только один раз без необходимости выносить их отдельно;
- использовать `readonly`, если значение не должно изменяться;
- предпочитать небольшие функции с одной ответственностью;
- избегать глубокой вложенности;
- использовать ранний `return`, когда это делает код понятнее;
- не использовать классы без необходимости;
- не создавать абстрактные базовые классы только ради переиспользования нескольких строк кода.

---

## Angular

- использовать standalone components;
- не использовать NgModules для новой функциональности;
- использовать Angular Signals для локального состояния UI;
- использовать RxJS для асинхронных потоков и операций, где он действительно необходим;
- использовать `ChangeDetectionStrategy.OnPush`;
- использовать `inject()` вместо constructor injection, если это соответствует стилю проекта;
- не помещать бизнес-логику непосредственно в шаблоны;
- не обращаться к Supabase напрямую из компонентов;
- не создавать сложные компоненты с чрезмерным количеством ответственности;
- использовать lazy loading для крупных страниц и разделов.

---

## Angular Components

Каждый компонент должен иметь понятную ответственность.
